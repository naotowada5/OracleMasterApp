## 1. 進め方の全体方針

> **現在の進捗（2026-08-23 時点）:** Step 1〜4 が完了し、マイルストーンM1〜M4 に到達。Step 5 は T5-1（手動結合確認）と T5-2（E2Eテスト）が完了。残りは T5-3（非機能確認）以降と Step 6（リリース）。
> dev環境（ap-northeast-1）には8API・問題34問が投入済みで、ローカルのフロントエンドから実APIに接続して動作する。

以下の順序で進める。

```
13_infra（AWS基盤・DynamoDB・Cognito）
   └─▶ 12_backend（Lambda API）
          └─▶ 14_script（初期データ投入）
          └─▶ 11_frontend（React PWA画面）
                 └─▶ 結合・E2Eテスト
                        └─▶ リリース
```

**理由:**
- フロントエンドは実APIとCognitoがないと画面を繋ぎ込めない。
- バックエンドはDynamoDBテーブル・Cognito User Poolがないと動かせない。
- 初期データ投入スクリプトはDynamoDBテーブル定義（属性・GSI）が確定していないと作れない。

このため、まず**インフラ（CDK）を最初に作り切り**、次にバックエンド、初期データ投入とフロントエンドは並行可能、最後に結合する。この順序どおりに Step 1〜4 を完了済み。

各タスクは対応する基本設計書へのリンクを付けているので、実装時はそちらを一次情報として参照すること。

## 4. 進め方の補足

- 各タスクの実装順序は上記が基本だが、**T1-3（DynamoDBテーブル定義）だけは最優先**で確定させること。バックエンド・投入スクリプト・フロントエンドの型定義がすべてこれに依存する。
- フロントエンド（Step4）はバックエンド（Step2）と並行して着手してよいが、その場合はAPIレスポンス形式（[API共通設計](../02_sd/02_API設計/API共通設計.md)）を先にモック化し、後から実APIに差し替える。
- Phase3スコープ（S-04の活性化、API-05/06実装、F-10進捗管理）は本タスク一覧に含めない。Phase1完了後に別途タスク分割する。

### 実装時の申し送り

- **Lambdaランタイムは Node.js 22.x**。設計当初の 20.x が非推奨化したため要件定義書 v1.3 で変更済み。
- **Lambdaのバンドルは事前ビルド方式**。CDKの `NodejsFunction` はローカルバンドリング失敗時にDockerへフォールバックし、Docker未導入の環境でデプロイできなくなるため採用していない。`13_infra` の npm スクリプトが `12_backend` のビルドを自動実行する。
- **問題データの投入は冪等**。IDを問題文等から決定的に生成しているため、同じデータを繰り返し投入しても重複しない。問題文を変更した場合は別レコードになる点に注意（`14_script` の `npm run purge:dev` で作り直す）。
- **dev環境のCORS許可オリジンは `http://localhost:5173`**。フロントエンドの開発サーバはこのポートで起動すること。
- **フロントエンドの接続先は `11_frontend/.env`** で切り替える（APIのURL、Cognito User Pool ID・Client ID）。いずれもクライアントに埋め込まれる公開値。
- **T3-4（各資格500問以上への拡充）は継続作業**。`14_script/data` のJSONに追記し `npm run validate` を通してから投入する。フロントエンド開発と並行して進められる。
