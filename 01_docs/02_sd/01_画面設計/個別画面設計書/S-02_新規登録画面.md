# S-02 新規登録画面

| 項目 | 内容 |
|---|---|
| 画面ID | S-02 |
| 画面名 | 新規登録画面 |
| Phase | Phase 1 |
| 認証要否 | 不要 |
| 関連機能ID | F-01 |

## 1. 概要

新規ユーザーがメールアドレス・パスワードを入力してアカウントを作成し、メール認証（確認コード入力）を経て利用開始できるようにする画面。Cognito のサインアップ／確認フローを利用する。

## 2. 画面イメージ

```
┌─────────────────────────┐
│  ＜ 新規登録              │
├─────────────────────────┤
│  表示名                  │
│  [                    ]  │
│                         │
│  メールアドレス           │
│  [                    ]  │
│                         │
│  パスワード              │
│  [                    ]  │
│                         │
│  パスワード（確認）        │
│  [                    ]  │
│                         │
│  ┌─────────────────┐    │
│  │    登録する      │    │
│  └─────────────────┘    │
└─────────────────────────┘

  ── メール認証コード入力（登録後）──
┌─────────────────────────┐
│  確認コードを入力してください │
│  [      ]                │
│  ┌─────────────────┐    │
│  │    確認する      │    │
│  └─────────────────┘    │
│  コードを再送信            │
└─────────────────────────┘
```

## 3. 表示項目

| 項目名 | 種別 | 必須 | 説明 |
|---|---|---|---|
| 表示名 | テキスト入力 | 必須 | Users テーブルの `displayName` として保存 |
| メールアドレス | テキスト入力 | 必須 | Cognito ユーザー名（一意） |
| パスワード | パスワード入力 | 必須 | Cognito パスワードポリシーに準拠 |
| パスワード（確認） | パスワード入力 | 必須 | パスワードと一致すること |
| 登録するボタン | ボタン | - | Cognito SignUp 実行 |
| 確認コード入力欄（第2ステップ） | テキスト入力 | 必須 | Cognito ConfirmSignUp 用の確認コード |
| コードを再送信リンク | リンク | - | Cognito ResendConfirmationCode |

## 4. 操作・イベント

| No | 操作 | 処理内容 | 遷移先 |
|---|---|---|---|
| 1 | 項目入力後「登録する」押下 | 入力チェック → Cognito SignUp 実行 → 確認コード入力ステップへ切替 | 同画面（第2ステップ表示） |
| 2 | 確認コード入力後「確認する」押下 | Cognito ConfirmSignUp 実行 → Users テーブルへの初期レコード作成はバックエンド側（初回ログイン時 or ポストコンファーム Lambda トリガー）で実施 | S-01 ログイン画面（「登録が完了しました。ログインしてください」表示） |
| 3 | 「コードを再送信」押下 | Cognito ResendConfirmationCode 実行 | 同画面 |

## 5. 入力チェック仕様

| 項目 | チェック内容 |
|---|---|
| 表示名 | 必須、1〜50文字 |
| メールアドレス | 必須、メール形式、Cognito 側で重複チェック（既存メールはエラー） |
| パスワード | 必須、8文字以上、英大文字・英小文字・数字を含む（Cognito パスワードポリシーに準拠） |
| パスワード（確認） | パスワードと完全一致 |
| 確認コード | 必須、数字6桁 |

## 6. 使用する外部インターフェース

- Amazon Cognito User Pool（`SignUp` / `ConfirmSignUp` / `ResendConfirmationCode`）
- Users テーブルへの初期レコード作成（`userId`=Cognito sub, `email`, `displayName`, `createdAt`）は、Cognito の Post Confirmation Lambda トリガー、または初回ログイン時にバックエンドが `GET /users/me` の初回アクセスで自動作成する（実装方式は詳細設計で確定）

## 7. エラーハンドリング

| ケース | 表示内容 |
|---|---|
| メールアドレス重複 | 「このメールアドレスは既に登録されています」 |
| パスワードポリシー違反 | 「パスワードは8文字以上で、英大文字・英小文字・数字を含めてください」 |
| 確認コード誤り | 「確認コードが正しくありません」 |
| 確認コード期限切れ | 「確認コードの有効期限が切れています。再送信してください」 |

## 8. 備考

- Phase 1 では法人一括登録・SSO等は対象外（要件定義書 §1.3 の法人利用は将来検討）。
