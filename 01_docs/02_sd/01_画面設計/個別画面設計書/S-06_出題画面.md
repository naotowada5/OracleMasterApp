# S-06 出題画面

| 項目 | 内容 |
|---|---|
| 画面ID | S-06 |
| 画面名 | 出題画面 |
| Phase | Phase 1 |
| 認証要否 | 必要 |
| 関連機能ID | F-04 |

## 1. 概要

問題文・選択肢を表示し、単一選択／複数選択それぞれの操作フローで回答を受け付ける画面。出題番号・残り時間を表示する。

## 2. 画面イメージ（要件定義書 §4.3 より）

```
┌─────────────────────────┐
│  問題 5 / 20  残り 24:31 │
├─────────────────────────┤
│  次のSQL文で正しいものは？│
│  ...（問題文）...        │
│                         │
│  A. SELECT * FROM ...   │
│  B. INSERT INTO ...     │
│  C. UPDATE SET ...      │
│  D. DELETE FROM ...     │
└─────────────────────────┘
```

```
┌─────────────────────────┐
│  問題 8 / 20  残り 21:05 │
├─────────────────────────┤
│  [複数選択] 正しいものを │
│  2つ選んでください        │
│                         │
│  ☐ A. ...               │
│  ☑ B. ...               │
│  ☐ C. ...               │
│  ☑ D. ...               │
│  ☐ E. ...               │
│                         │
│  ┌────────────────┐      │
│  │      決定      │      │
│  └────────────────┘      │
└─────────────────────────┘
```

## 3. 表示項目

| 項目名 | 種別 | 説明 |
|---|---|---|
| 出題番号 | テキスト | 「◯ / 総問題数」形式 |
| 出題数不足の警告 | テキスト（閉じるボタン付き） | S-05 で対象問題が指定数に満たなかった場合のみ表示（[S-05](S-05_出題設定画面.md) §5）。S-05 は警告表示後ただちに本画面へ遷移するため、実際に読めるのはここになる。閉じると再表示しない |
| 残り時間 | テキスト（タイマー） | 制限時間設定時のみ表示。`mm:ss` 形式でカウントダウン |
| 問題種別バッジ | テキスト | 複数選択問題の場合のみ「[複数選択] ◯つ選んでください」を表示（`correctCount` を反映） |
| 問題文 | テキスト | `questionText` |
| 選択肢 | ラジオボタン（single）／チェックボックス（multiple） | 最大10択。ラベル（A, B, C...）+ `choiceText` |
| 決定ボタン | ボタン | 複数選択問題のみ表示。1つ以上選択済みの場合に活性化 |

## 4. 操作・イベント

| No | 操作 | 処理内容 | 遷移先 |
|---|---|---|---|
| 1 | 画面表示時（1問目） | S-05 で取得済みの出題リストから1問目を表示。タイマー開始（制限時間設定時） | - |
| 2 | 単一選択問題: 選択肢タップ | 即座に正誤判定（クライアント側では選択のみ記録、正誤確定はAPI応答に基づく） → `PUT /sessions/{sessionId}` で回答送信 | S-07 解説画面 |
| 3 | 複数選択問題: 選択肢タップ（複数可） | 選択状態をトグル。正誤判定は行わない | 同画面（選択状態更新） |
| 4 | 複数選択問題: 「決定」ボタン押下 | 選択済みの選択肢ID集合を `PUT /sessions/{sessionId}` で送信し正誤判定を取得 | S-07 解説画面 |
| 5 | 制限時間到達（タイマー0） | 現在の状態を確定し、セッションを終了状態（`expired`）としてサーバーに通知 | S-09 解答結果画面 |

## 5. 採点仕様（要件定義書 F-04 準拠）

- 単一選択問題: 選択した1つの選択肢IDが正解選択肢IDと一致すれば正解。
- 複数選択問題: 選択した選択肢ID集合と正解選択肢ID集合が**完全一致**した場合のみ正解。1つでも過不足があれば不正解（部分点なし）。
- 正誤判定はクライアントで完結させず、サーバー（Lambda）側で `OR_M_CHOICE.isCorrect` を突き合わせて判定し、レスポンスとして返す（クライアントに正解を事前に渡さない設計。詳細は [API-08](../../02_API設計/個別API設計書/API-08_セッション更新.md) 参照）。

## 6. 使用API

| API | 用途 |
|---|---|
| `PUT /sessions/{sessionId}` | 回答送信・正誤判定取得・回答履歴登録 |

## 7. エラーハンドリング

| ケース | 表示内容 |
|---|---|
| 回答送信失敗（通信エラー） | 「回答の送信に失敗しました。再試行してください」。選択状態は保持し、再送信可能とする |
| セッションが既に `completed`/`expired` の場合の回答送信 | 「このセッションは終了しています」と表示し、S-09 へ遷移 |

## 8. 備考

- 選択肢の表示順は `OR_M_CHOICE.sortOrder` を基準とするが、Phase1では出題の都度シャッフルするかは詳細設計（フロントエンド実装）で決定する。
- 残り時間はクライアント側でカウントダウン表示するが、最終的な時間切れ判定はサーバー側の `startedAt` + `timeLimitMin` との比較でも二重チェックする。
