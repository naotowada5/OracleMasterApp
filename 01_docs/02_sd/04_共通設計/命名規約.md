# 命名規約

本基本設計書一式および今後のPhase2/3の設計追加時に一貫性を保つための命名規約。

## 1. ドキュメントID

| 対象 | ID形式 | 例 | 採番規則 |
|---|---|---|---|
| 画面 | `S-NN`（2桁連番） | S-01, S-02 | 要件定義書§4.1のIDを継承。新規画面追加時は末尾に連番を追加（欠番を詰めない） |
| API | `API-NN`（2桁連番） | API-01 | エンドポイント一覧の掲載順に採番。エンドポイント自体の識別は必ずHTTPメソッド+パスで行う |
| テーブル/エンティティ | `T-NN`（2桁連番） | T-01 | 要件定義書§6.1のテーブル掲載順に採番 |

## 2. DynamoDB命名規約

| 対象 | 規則 | 例 |
|---|---|---|
| テーブル名 | 環境プレフィックス + PascalCase | `dev-Questions`, `prod-ExamSessions` |
| 属性名 | camelCase | `qualificationId`, `correctCount` |
| GSI名 | `{属性名}-index` | `qualificationId-index` |
| ID属性値 | UUID v4（`qualificationId`のみ資格コード文字列） | `q1e2f3a4-...` |

## 3. API命名規約

| 対象 | 規則 |
|---|---|
| パス | 複数形リソース名（`/questions`, `/sessions`）。個別リソースは `{resourceId}` パスパラメータ |
| クエリパラメータ | camelCase（`qualificationId`, `nextToken`） |
| エラーコード | UPPER_SNAKE_CASE（`VALIDATION_ERROR`） |

詳細は [API共通設計](../02_API設計/API共通設計.md) を参照。

## 4. フロントエンド命名規約（参考・詳細設計で確定）

- コンポーネント名: 画面IDに対応する形（例: `S05OutputSettingPage` 等）を目安とし、詳細はフロントエンド詳細設計で定める。
- 本基本設計書では、画面ID（S-01〜S-09）・API ID（API-01〜API-10）・テーブルID（T-01〜T-07）を横断的な参照キーとして使用する。

## 5. Phase表記

- 「Phase 1」「Phase 2」「Phase 3」の表記は要件定義書§2.1, §11の定義に統一する。
- Phase 3実装だが Phase 1/2 でUI上のみ存在する画面・APIには、各ドキュメントの見出し直下に注意書き（例: 「本設計はインターフェース定義のみ。Phase1・Phase2では未実装」）を明記する（[S-04](../01_画面設計/個別画面設計書/S-04_問題作成インポート画面.md), [API-05](../02_API設計/個別API設計書/API-05_問題インポート.md), [API-06](../02_API設計/個別API設計書/API-06_AI問題生成.md) 参照）。
