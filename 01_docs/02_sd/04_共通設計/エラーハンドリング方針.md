# エラーハンドリング方針

## 1. 目的

フロントエンド・バックエンドを通じて一貫したエラー処理を行い、ユーザーには分かりやすい日本語メッセージを、開発者にはログから原因追跡できる情報を提供する。

## 2. レイヤー別方針

### 2.1 API Gateway 層

- Cognito Authorizer によるトークン検証失敗は 401 を自動応答（[API共通設計](../02_API設計/API共通設計.md) 参照）。
- リクエストの基本的な型検証（必須パラメータの有無等）は API Gateway のリクエストバリデータでも一部実施し、Lambda呼び出し前に弾けるものは弾く（要件定義書§9.4）。

### 2.2 Lambda（バックエンド）層

- 各Lambda関数は共通のエラーハンドリングミドルウェア（または共通関数）を通し、[API共通設計](../02_API設計/API共通設計.md) §4.2 のエラーレスポンス形式に統一する。
- 想定内エラー（バリデーションエラー、リソース不存在、権限エラー等）は明示的に検知し、適切なHTTPステータス・エラーコードを返す。
- 想定外の例外（DynamoDBの一時的な障害等）は共通のcatch節で捕捉し、`500 INTERNAL_ERROR` または `503 EXTERNAL_SERVICE_ERROR` として返す。スタックトレース等の内部情報はレスポンスに含めず、CloudWatch Logsにのみ出力する。
- 入力サニタイズ: 文字列項目はDynamoDBへの書き込み前にトリム・長さ制限を行い、想定外の制御文字等を除去する（要件定義書§9.4）。

### 2.3 フロントエンド（React）層

- APIエラーレスポンスの `error.code` を判定し、画面ごとのメッセージ（各[個別画面設計書](../01_画面設計/個別画面設計書/)のエラーハンドリング節）に変換して表示する。
- 401受信時は保持しているトークンを破棄し、S-01ログイン画面へ強制遷移する（[認証・認可設計](認証・認可設計.md) 参照）。
- 403/404/409等は画面固有のメッセージで案内し、致命的でない場合は画面遷移させずリトライを促す。
- 通信断・タイムアウトは共通のトースト通知（「通信エラーが発生しました。時間をおいて再度お試しください」）で案内する。

## 3. 共通エラーコード対応表（再掲・フロントエンド表示指針）

| コード | HTTPステータス | フロントエンド既定表示 |
|---|---|---|
| `VALIDATION_ERROR` | 400 | `error.details` があればフィールド単位で表示、なければ `error.message` をそのまま表示 |
| `UNAUTHORIZED` | 401 | ログイン画面へ強制遷移 |
| `FORBIDDEN` | 403 | 「この操作を行う権限がありません」 |
| `NOT_FOUND` | 404 | 「指定されたデータが見つかりません」 |
| `CONFLICT` | 409 | 画面固有メッセージ（例: 「このセッションは終了しています」） |
| `INTERNAL_ERROR` | 500 | 「エラーが発生しました。時間をおいて再度お試しください」 |
| `EXTERNAL_SERVICE_ERROR` | 503 | 「外部サービスとの連携でエラーが発生しました」（Phase3のAI機能等） |

## 4. リトライ方針

- 一覧取得系（GET）のネットワークエラーは、ユーザー操作（再読み込みボタン）によるリトライを基本とし、自動リトライは行わない（多重リクエスト防止）。
- 回答送信（[API-08](../02_API設計/個別API設計書/API-08_セッション更新.md)）等の更新系APIは、冪等性を担保した上で、ユーザー操作によるリトライのみ許可する（自動リトライによる二重採点を防ぐ）。

## 5. Lambdaタイムアウトの扱い

- 通常APIのLambdaタイムアウトは要件定義書§8.1のレスポンス目標（p95で500ms以内）を踏まえ、余裕を持った値（例: 10秒）に設定する。
- AI関連API（Phase3, [API-06](../02_API設計/個別API設計書/API-06_AI問題生成.md)）はAnthropic Claude API呼び出しを含むため、より長いタイムアウト（要件定義書§8.1のAI系レスポンス目標10秒を踏まえ、余裕を持たせた値）を個別に設定する。
- 30秒超過のLambdaタイムアウトはCloudWatchで検知しアラートを上げる（要件定義書§10.4、[ログ・監視設計](ログ・監視設計.md) 参照）。
