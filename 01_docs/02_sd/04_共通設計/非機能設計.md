# 非機能設計

要件定義書 §8 の非機能要件を、基本設計の観点（実現方式）に落とし込んだもの。数値目標自体は要件定義書を正とし、本書では「どう実現するか」を記載する。

## 1. 性能

| 要件（要件定義書§8.1） | 実現方式 |
|---|---|
| APIレスポンス500ms以内（p95、通常時） | DynamoDBオンデマンドキャパシティ＋GSIによる効率的なQuery（Scanは資格一覧等の小規模データのみに限定、[テーブル一覧](../03_データベース設計/テーブル一覧.md)参照）。Lambdaのコールドスタート対策として必要に応じ Provisioned Concurrency を検討 |
| AI生成・AI解説10秒以内（Phase3） | Anthropic Claude API呼び出しのタイムアウト・リトライ設定を個別に調整（[API-06](../02_API設計/個別API設計書/API-06_AI問題生成.md)参照） |
| 同時接続100ユーザー（Phase1） | Lambda同時実行数・API Gatewayスロットリングをこの規模に対して余裕を持たせて設定 |
| Webアプリ初回表示3秒以内 | Amplifyでのビルド最適化（コード分割、画像最適化）、Service Workerによるアプリシェルキャッシュ（PWA） |

## 2. 可用性

[ログ・監視設計](ログ・監視設計.md) §4 を参照。

## 3. PWA・オフライン対応

| 要件（要件定義書§8.5） | 実現方式 |
|---|---|
| ホーム画面追加 | Web App Manifest（`manifest.json`）を配置し、アイコン・テーマカラー等を定義 |
| Service Workerによるアプリシェルキャッシュ（Phase1） | 静的アセット（JS/CSS/画像）をキャッシュし、オフライン時もアプリの起動画面までは表示可能にする。問題データそのもののオフラインキャッシュはPhase2で本格対応 |
| ダークモード | OSの `prefers-color-scheme` に追従するCSS設計 |

## 4. 対応ブラウザ・デバイス（要件定義書§8.4）

| プラットフォーム | 対応バージョン |
|---|---|
| PCブラウザ | Chrome / Edge / Safari 各最新2バージョン |
| スマートフォンブラウザ | iOS Safari 15以上、Android Chrome最新2バージョン |
| 画面サイズ | 5〜6.7インチのスマートフォン、PC画面（レスポンシブ対応） |

フロントエンドはこれらのブラウザでの動作確認をPlaywright E2Eテストの対象環境に含める（要件定義書§10.1）。

## 5. スケーラビリティ

- DynamoDBオンデマンドキャパシティによる自動スケール（要件定義書§8.3）。
- Lambda並行実行によるスケールアウト。
- 将来的なユーザー増加（100ユーザー超）に対応できるよう、GSI設計（[テーブル一覧](../03_データベース設計/テーブル一覧.md)）はパーティション分散を意識したキー設計とする。

## 6. データ量

- 問題データ: 各資格500問以上（要件定義書§8.1）。Phase1リリース時点で不足する場合は資格ごとに順次拡充。
- Phase1リリース後のデータ増加（ExamSessions/AnswerHistories）を見据え、DynamoDBのオンデマンドキャパシティで対応する（Phase1では明示的なアーカイブ/削除ポリシーは設けないが、Phase3の進捗管理機能実装時に保持期間ポリシーを再検討する）。

## 7. ユーザビリティ

- 日本語UI（全画面対応、要件定義書§8.5）。
- アクセシビリティ設定（フォントサイズ変更等）はPhase2で対応。Phase1は標準サイズのみ。

## 8. セキュリティ（要件定義書§9との対応）

セキュリティ要件の実現方式は [認証・認可設計](認証・認可設計.md) に集約して記載する。データ保護（DynamoDB暗号化、S3パブリックアクセスブロック等）は [システム構成・環境設計](システム構成・環境設計.md) §5 を参照。
